# Code generation options

`TsCodeGenerator` turns one or more attributed PHP classes into a single TypeScript (or JavaScript) file.

```php
use Murdej\TsLinkPhp\TsCodeGenerator;

$tsg = new TsCodeGenerator();
$tsg->add(UserCL::class, '/api/user');
$tsg->add(CartCL::class, '/api/cart');

file_put_contents('./tslClasses.ts', $tsg->generateCode());
```

## `add(classDef, endpoint = null, className = null)`

Call once per class you want in the generated file:

- `classDef` — a class name, or an already-built `ClassReflection`.
- `endpoint` — the URL the generated class should call. If omitted, the generated class won't set a
  default URL — set `.url` on the instance yourself before calling any method.
- `className` — override the generated TypeScript class name (defaults to the PHP class's short name).

## Output format

```php
$tsg->format = 'ts'; // or 'js'
```

Controls both the syntax emitted for your service classes and which base implementation
(`BaseCL.ts`/`BaseCL.js`) gets embedded.

```php
$tsg->useJsModules = true; // false: plain classes, no import/export — for direct <script> tag usage
```

## Sharing one `BaseCL` across multiple generated files

By default, every file generated by `TsCodeGenerator` inlines the full `BaseCL` implementation. If you
generate several files (e.g. one per bounded context) and don't want it duplicated in each, point them at
a shared copy instead:

```php
$tsg->baseClassName = 'BaseCL';       // default
$tsg->baseClassRequire = '../BaseCL'; // import path; when set, BaseCL is no longer inlined
```

## `exportSingleton`

```php
$tsg->exportSingleton = true; // default
```

When enabled, each generated class is accompanied by a ready-to-use singleton export
(`export const userCL = new UserCL();`), so consumers can just `import { userCL } from './tslClasses'`
instead of instantiating the class themselves.

## Import paths

Types pulled in via [`#[ClientMethodType]`'s `importFrom`](client-methods.md#clientmethodtype--overriding-a-type)
or [`#[ClientMethodImport]`](client-methods.md#clientmethodimport--adding-imports) are rewritten through
`baseImportPath`:

```php
$tsg->baseImportPath = [
    '@npm:' => '',    // "@npm:some-package" -> import from "some-package" (npm package, no rewrite)
    ''      => '../', // everything else -> prefixed with "../" (relative to the generated file)
];
```

Pass a single string instead of a map to apply the same prefix to every import.

Type names prefixed with `TsCodeGenerator::$importClassPrefix` (default `'@'`) are emitted as value
imports (`import { Foo }`) rather than type-only imports (`import { type Foo }`) — this is how
`new ClassName`-style return types (see [Client methods & types](client-methods.md#clientmethodtype--overriding-a-type))
end up importable as a real class instead of just a type.
